# 文档入口与会话分工

更新日期：2026-09-07。以下分工由项目所有者在产品规划会话中明确约定。

## 会话职责

**产品规划会话（本会话）**负责产品规划、项目分析、需求讨论和答疑。可以阅读代码、文档和已有验证结果来判断现状；后续产物统一写入本目录，不在本会话修改业务代码、执行数据迁移或部署服务。

**开发会话（其他会话）**读取本目录的规划产物及当前代码，按用户在该会话授权的范围实施、测试并交付。上述规划会话边界不限制开发会话开展已授权的研发工作。

规划结论不能只留在聊天记录中。新增需求、范围变更、产品决策及有复用价值的答疑，应更新对应文档；独立主题可新增文档并在此登记。简单状态答复引用现有文档即可。

## 规划与开发交接

1. 规划会话在文档中写清目标、本期范围、不包含的内容、关键规则、依赖、验收标准和待确认事项。建议与已确认决定分开标注。
2. 开发会话先阅读本页、对应期次计划和最近交付文档，再核对代码现状；不要仅凭早期评估中“未实现”的描述重复开发。
3. 开发只执行该会话已获授权的期次。文档中的后续方向不代表自动获准连续开发；发现重大范围变化，应先记录差异并与用户对齐。
4. 每期交付后，在本目录记录已完成范围、可操作的验收步骤、实际测试结果、遗留问题及下一期建议。区分“开发完成”“测试通过”和“用户验收通过”。
5. 规划会话可根据开发交付和用户反馈调整后续规划；逐期验收、逐期确认后推进。

发生不一致时，以用户最新明确决定为准，并同步更新相关文档。判断实际已实现能力时，以当前代码和可核对的交付证据为准；文档不替代代码核验，也不把规划当成现状。
